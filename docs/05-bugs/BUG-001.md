# BUG-001: A API expõe o campo interno `_id` nos itens de proventos e descontos

| Campo | Valor |
|---|---|
| Status | Aberto |
| Severidade | Baixa |
| Prioridade | Média |
| Encontrado em | Execução manual (roteiro), caso CT-AUT-06 |
| Condição / requisito | CND-08, RN-02 (a resposta não deve conter dados internos) |
| Ambiente | Windows, Node.js, Git Bash, `curl`, aplicação v1.0.0 em `localhost:3000` |
| Evidência | `docs/evidencias/CT-AUT-06.txt` |

## Descrição
As respostas de `GET /api/payslips` e `GET /api/payslips/latest` incluem um campo `_id` em cada item das listas `earnings` e `deductions`. São identificadores internos do banco que não fazem parte do contrato da API (`openapi.yaml`) e não têm utilidade para o funcionário.

## Passos para reproduzir
1. Iniciar a aplicação com `npm start`.
2. Fazer login com `ana@empresa.com` e `Senha@123` e guardar o token.
3. Executar `curl -s localhost:3000/api/payslips/latest -H "Authorization: Bearer <token>" | grep "_id"`.

## Resultado obtido
Status 200. O JSON contém `"_id"` dentro de itens de `earnings` e `deductions`.

## Resultado esperado
A resposta contém apenas os campos documentados no `openapi.yaml` (`description` e `amount` em cada item), sem identificadores internos.

## Impacto
Baixo. O valor exposto é o id de uma linha do holerite (não de funcionário nem de senha), então não há vazamento de dado financeiro de terceiros. Ainda assim, viola a condição CND-08 e expõe detalhes de implementação do banco.

## Causa provável (análise do código, a confirmar)
No `src/models.js`, `earnings` e `deductions` são declarados como `[line]` com um objeto simples. O Mongoose trata cada item como subdocumento e cria um `_id` automaticamente. O `toDto` em `src/app.js` repassa os arrays sem filtrar.

## Sugestão de correção
Declarar o subdocumento sem id (`new mongoose.Schema({ description: String, amount: Number }, { _id: false })`) ou mapear os itens no `toDto` para devolver só `description` e `amount`.
