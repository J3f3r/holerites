# OBS-001: O token continua válido na API depois de clicar em "Sair" no site

| Campo | Valor |
|---|---|
| Tipo | Observação de design (não classificada como defeito) |
| Status | Em aberto, aguardando decisão |

| Condição / requisito | RN-01 |
| Evidência | `docs/04-sessoes-exploratorias.md` (notas de 20:51) e o `.docx` de evidências da EXP-API |

## O que foi observado
Com a Ana logada, o token foi copiado e foi clicado em **Sair** no site. Em seguida, `GET /api/payslips/latest` com esse token respondeu `200` e devolveu o holerite da Ana (`netPay: 5745`).

## Por que não é classificada como defeito
A API não tem endpoint de logout, e o **Sair** do site só limpa o Session Storage do navegador. O token é um JWT sem estado, com validade de 1 hora e sem lista de revogação, o que é uma escolha de arquitetura comum. O requisito não define que o logout deva invalidar o token no servidor.

## Risco
Se o token for copiado ou vazar, quem o possui continua com acesso por até 1 hora, mesmo depois de a pessoa sair. O acesso é sempre restrito aos holerites do dono do token.

## Decisão pendente
Aceitar o risco (documentando-o) ou adotar uma medida: reduzir a validade do token, ou criar revogação no servidor. Reavaliar na versão com backend em Java.
