# BUG-005: Corpo da requisição acima do limite retorna 500 em vez de 413

| Campo | Valor |

| Status | Aberto |
| Severidade | Média |
| Prioridade | Média (corrigir junto com o BUG-002) |
| Encontrado em | Sessão exploratória EXP-API (16:21), VADER: Erros |
| Condição / requisito | CND-17 |
| Ambiente | Windows, Node.js, Git Bash, `curl`, aplicação v1.0.0 em `localhost:3000` |
| Evidência | `docs/04-sessoes-exploratorias.md` (notas de 16:21) e teste `EXP-API corpo acima do limite` em `tests/api/api.test.js` |

## Descrição
Um `POST /api/auth/login` com corpo JSON de cerca de 200 KB (campo `email` com 200.000 caracteres) recebe `500` com `{"message":"Erro interno."}`. O servidor rejeita o corpo por ser maior que o limite padrão do `express.json()` (100 KB), mas o erro é devolvido como falha interna, em vez de `413 Payload Too Large`.

## Passos para reproduzir
1. Iniciar a aplicação com `npm start`.
2. Enviar `POST /api/auth/login` com `Content-Type: application/json` e um campo `email` com 200.000 caracteres.
3. Observar o status e a mensagem.

## Resultado obtido
`500` e `{"message":"Erro interno."}`.

## Resultado esperado
`413` com mensagem clara, por exemplo "Requisição grande demais.".

## Impacto
Médio, por consistência com o BUG-002 (mesma causa e mesma correção). Não há vazamento nem queda do servidor. Um corpo grande é raro em uso normal, mas é um dos primeiros testes que alguém faz contra uma API, e a resposta 500 distorce o monitoramento.

## Causa provável (a confirmar)
A mesma do BUG-002: o tratador de erros em `src/app.js` ignora `err.status` e responde sempre 500. O erro do `body-parser` traz status 413.

## Sugestão de correção
Usar `err.status` (quando for 4xx) no tratador de erros. A mesma correção resolve o BUG-002 e este.

## Teste que cobre o defeito
`tests/api/api.test.js`: "EXP-API corpo acima do limite deveria retornar 413" (marcado como `todo: 'BUG-005'` até a correção).
